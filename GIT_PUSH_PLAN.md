## 1. Important workflow rules

There are **two rounds**:

1. **Round A – Code:** each member commits and pushes only their assigned code, in the order A1–A5.
2. **Round B – Results:** members run their assigned scripts on their own Windows laptops and push the outputs produced by those runs, in the order B1–B6.

Follow these rules:

- Everyone has the same original project ZIP extracted locally. This is the **source folder**. Do not use it as the shared Git working copy.
- Everyone has a separate **Git working copy** cloned from GitHub. All commits and pushes happen from this Git working copy.
- The Git working copy can be stored anywhere on each person's computer. The absolute folder path does **not** need to match between teammates.
- For consistency, name the Git working folder `pathsnap`.
- Copy only the files assigned to you from the source folder into your Git working copy.
- `GIT_PUSH_PLAN.md` and `CONTRIBUTIONS.md` are team-internal planning files and must **not** be uploaded to GitHub. Keep them in the source folder/local copies only.
- Do not copy the source folder's `.git` directory into the Git working copy.
- Do not copy the source folder's virtual environment (`venv` or `.venv`) into the Git working copy.
- Do not copy `outputs/` from the ZIP. Round B outputs must be generated by running the scripts on the member's own laptop.
- Each person must commit using their own Git name and email. Do not add co-author lines.
- Do not edit another member's assigned files unless the team coordinates it first.
- Before every push after the first one, run `git pull --rebase`.
- Never force-push (`git push --force`).

## 2. Terminal choice: PowerShell or CMD

Commands below are written primarily for **Windows PowerShell**. Where the syntax differs, the **CMD alternative is shown in brackets**.

Open PowerShell or Command Prompt in the required folder. In VS Code, use **Terminal → New Terminal** and select PowerShell or Command Prompt.

### Common command differences

| Task | PowerShell | CMD |
|---|---|---|
| Show current folder | `Get-Location` | `cd` |
| Change folder | `Set-Location "D:\path with spaces"` | `cd /d "D:\path with spaces"` |
| Create directory | `New-Item -ItemType Directory -Force "folder"` | `mkdir "folder"` |
| Copy file | `Copy-Item -LiteralPath "source" -Destination "destination"` | `copy "source" "destination"` |
| Copy directory recursively | `Copy-Item -LiteralPath "source" -Destination "destination" -Recurse` | `xcopy "source" "destination" /E /I /H` |
| Remove a directory | `Remove-Item -Recurse -Force "folder"` | `rmdir /S /Q "folder"` |
| Activate venv | `.venv\Scripts\Activate.ps1` | `.venv\Scripts\activate.bat` |
| Set environment variable | `$env:NAME="value"` | `set NAME=value` |

Use quotation marks around Windows paths that contain spaces.

# 6. Troubleshooting

## `git push` is rejected because the remote contains work

Do not force-push. Run:

```powershell
git pull --rebase
git push
```

If Git reports conflicts, stop and contact the team rather than resolving another member's files without coordination.

## `git` is not recognised

Install Git for Windows, close and reopen the terminal, and check:

```powershell
git --version
```

## `python` is not recognised

Install Python for Windows with **Add Python to PATH** enabled. Reopen the terminal and check:

```powershell
python --version
```

## PowerShell refuses to activate the virtual environment

Run:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

Alternatively, use CMD:

```cmd
.venv\Scripts\activate.bat
```

## A file is missing after copying

Check that `$S` (PowerShell) or `%S%` (CMD) points to the extracted source folder, and confirm the source file exists before copying it.

PowerShell:
```powershell
Test-Path -LiteralPath "$S\src\config.py"
```

CMD:
```cmd
dir "%S%\src\config.py"
```

## Accidentally staged the wrong files

Before committing, inspect:

```powershell
git status
```

To unstage everything without deleting local files:

```powershell
git restore --staged .
```

Then stage only your assigned files.

## A generated output folder does not exist

Do not create fake result files or copy outputs from the ZIP. Run the relevant script, inspect its output location, and coordinate with the team if the output path differs from this plan.

## 7. Never push these files

- Original dataset files (`data/raw/train`, `data/raw/student_test`, etc.)
- `data/evaluation/`
- `.venv/` or `venv/`
- `__pycache__/` and `.pyc` files
- Passwords, API keys, access tokens or credentials
- Temporary files or outputs copied from someone else's machine

**Final rule:** Each member pushes only their assigned code/results, in the order listed above. Always check `git status` before `git commit`.
